# 실제 flow 데이터로 재측정 — 라운드 4

> 2026-09-09 · 확신 등급: 실측✅ / 통제🟡 / 추정🟠 / 미재현⬜ / 철회❌
>
> 재현: `node bench/seed-flow.js [--noisy] --write` → `node bench/roundtrip.js [--noisy]`
> → `node bench/block-fusion.js 2965412` → `node bench/noise-stress.js` → `node bench/ladder.js`

라운드 1~3 은 전부 내가 쓴 문자열이었다. 인용 게이트는 문자열 대조라서, flow 를 한 바퀴 돌고 온
텍스트가 원문과 달라지면 그 자리에서 깨진다. 그래서 합성 12문서를 **실제 flow 프로젝트에 심고,
flow API 로 다시 읽어** 같은 게이트를 걸었다.

| 방 | 무엇 |
|---|---|
| `2969669` | 평문판 — `bench/docs.js` 의 SYNTHETIC 그대로 |
| `2969670` | 노이즈판 — 같은 12문서에 에디터 노이즈를 덧입힌 것(`bench/docs-noisy.js`) |

노이즈는 지어낸 게 아니다. 플로우가 만든 `시작가이드` 방(에디터로 쓰인 글)을 재서 나왔다 —
`&nbsp;` 글당 1~9개 · 이모지 글당 3~4개 · `htmlContent` 650~6,953자 · COMPS 가 TEXT 단일이 아님(TEXT/LINK, TEXT/IMAGE).
여기에 붙여넣기 자국(제로폭)·해시태그·멘션·표를 더했다. 심은 합계: nbsp 17 · 제로폭 7 · 이모지 11 · 해시태그 5 · 멘션 2 · 표행 6.
**수치 문자열은 한 글자도 건드리지 않았다.** 바뀐 건 그 주변뿐이다.

## ✅ API 왕복은 무손실이다

12문서를 심고 다시 읽어 심은 원문과 대조했다.

| 판 | 일치 | 다름 | 못 읽음 |
|---|---|---|---|
| 평문 | 12 | 0 | 0 |
| 노이즈 | 12 | 0 | 0 |

개행까지 포함해 같다. API 로 심은 글은 `content`(COMPS JSON)·`outContent`(플레인)에 원문이 그대로 들어가고
`htmlContent` 는 **빈 문자열**이다. → 왕복 자체는 게이트를 위협하지 않는다.
**단 이건 API 쓰기 경로에 대한 결과다.** 에디터로 쓴 글은 다르다 — 다음 절.

## 🔴 outContent 는 블록 경계를 지운다 — 게이트가 못 잡는 자리

에디터 글은 `htmlContent` 에 `<div>`/`<p>`/`<h2>`/`<br>` 로 블록이 나뉜다.
그런데 플레인 투영인 `outContent` 에는 그 경계에 **구분자가 없다.**

실측 (`node bench/block-fusion.js 2965412`) — 에디터 글 3건 · 블록 이음매 22곳 중 **3곳이 구분자 없이 융합**:
`"초대합니다!◾ 일시 :"` · `"싶은 누구나◾ 신청하기"` · `"진행되나요?플로우를 처"`.

h2 의 끝과 다음 div 의 시작이 한 문장이 된다.
**인용 게이트는 이걸 못 잡는다** — 게이트는 「인용이 원문에 실재하나」만 보는데 융합된 문자열은 실재하기 때문이다.
두 블록에 걸친 인용이 정당한 인용으로 통과한다.

→ `src/collect.js` 를 고쳤다. `htmlContent` 가 있으면 **블록 종료 태그(`</p> </div> </h*> </li> </tr> </td> <br> …`)를
개행으로 바꾼 뒤** 태그를 벗기고, 없을 때만 `outContent` 로 내려간다. 고친 뒤 융합 3곳 전부 사라졌다.
심은 데모 두 방은 `htmlContent` 가 비어 있어 영향이 없다(재실행으로 회귀 없음 확인).

⚠️ **표본이 글 3건이다.** 「13.6%」를 비율로 인용하지 않는다. **「실재한다」까지만 말한다.**

## ✅ 게이트가 견디는 선을 그었다 — 공백이냐 아니냐

노이즈판이 29/29 통과한 이유를 따로 쟀다. 내가 넣은 노이즈가 대부분 문장 **바깥**에 붙었기 때문이다.
그래서 인용 **안쪽 한가운데**에 한 글자를 넣고 다시 걸었다 (`node bench/noise-stress.js`, Gemini 0회).

| 인용 안에 낀 것 | 통과 |
|---|---|
| 공백 · `&nbsp;` · 제로폭 · 개행 | **29 / 29** |
| 이모지 · `*` · `\|` | **0 / 29** |

게이트의 1차 정규화가 지우는 문자냐 아니냐가 선이다. 지우지 않는 문자가 인용 안쪽에 끼면 1차·2차 둘 다 못 넘는다.
깨지는 방향은 **오폐기**(참인 주장을 버린다)라 안전한 쪽이지만, 에디터에서 숫자만 굵게 하거나 표가 값을 감싸면
재현율이 깎인다. ⬜ 실제로 그런 문서에서 얼마나 깎이는지는 아직 안 쟀다.

## 🟡 추출이 준 건 노이즈가 아니라 **모델 별칭**이었다

flow 노이즈판 첫 실행에서 17건이 나왔다. 라운드 3(깨끗한 합성, flash-lite)은 31건이었다.
그 사이에 바뀐 게 셋이라 — 모델 별칭 · 개행 붕괴 · 노이즈 — 하나씩 켰다 (`node bench/ladder.js`, 모델 `gemini-3.1-flash-lite` 고정).

| | 입력 | 추출 | 통과 | 폐기 |
|---|---|---|---|---|
| A | 합성 원문 (개행 있음) | 19 | 19 | 0 |
| B | A + 개행 붕괴 | 18 | 18 | 0 |
| C | flow 노이즈판 | 17 | 16 | **1** |

🔴 **라운드 3 의 31건은 별칭이 만든 숫자다.** 같은 입력·같은 채점에서
`gemini-flash-lite-latest` 31건 → `gemini-3.1-flash-lite` **19건**.
별칭은 언제든 다른 모델로 해석된다. **모델은 별칭이 아니라 버전으로 고정한다.**

개행 붕괴가 먹은 것은 1건, 노이즈가 먹은 것은 1건이다(A→C 순증감은 −5/+2 로 흔들린다 — `temperature 0` 이어도
배치가 무엇을 열거하는지는 안정적이지 않다). ⚠️ **각 칸이 1회 실행이다. 차이를 비율로 말하지 않는다.**

## 🔴 게이트가 처음으로 하나 잡았다 — 그런데 수치는 맞았다

라운드 1~3 은 주장 115건에 폐기 0건이었다. 실제 flow 데이터에서 처음 하나가 걸렸다.

```
✗ [post:2] "- 요청당 쿼리가 47회 나갑니다." (값 47) — 인용이 원문에 없음
```

원문은 `… - 목록 조회에서 N+1이 납니다. 요청당 쿼리가 47회 나갑니다. - p95 820ms …` 이다.
`47회` 는 **그 문서에 실재한다.** 모델이 앞줄의 불릿 `- ` 를 끌어다 붙여 **원문에 없는 문장**을 만들었을 뿐이다.

→ 게이트가 본 것은 「수치가 틀렸나」가 아니라 「인용이 실재하나」다. **참인 주장이 거짓 인용 때문에 버려졌다.**
게이트의 성질을 그대로 보여주는 건이라 남긴다.

원인은 노이즈가 아니라 내 코드였다. `collect.normalizeText` 가 `\s+` 를 공백 하나로 뭉개서
앞줄 불릿이 뒷문장 옆에 붙었다. **개행을 살리도록 고쳤다** — 게이트는 대조 전에 공백을 전부 지우므로
개행을 남겨도 판정은 안 바뀌고, 모델에게 줄 단서만 는다.

| flow 노이즈판 · `gemini-3.1-flash-lite` | 추출 | 통과 | 폐기 | 오귀속 |
|---|---|---|---|---|
| 개행 붕괴 (수정 전) | 17 | 16 | 1 | 0 |
| 개행 보존 (수정 후) | 17 | **17** | **0** | 0 |

지어낸 인용이 사라졌고 `post:2` 의 `47회` 가 돌아왔다.
⚠️ **양쪽 1회씩이다.** 「고쳐서 사라졌다」는 관측이고, 재현은 아직 1회다.

## ✅ scope/method 분리는 flow 데이터에서도 버텼다

| | 재현 | 오탐 |
|---|---|---|
| gold 의 method 3건 | **3/3** | **0/14** |

`820ms@post:2` · `320ms@post:3` → `"스테이징 · 동시 10 · 캐시 미적용"`, `280ms@comment:3-1` → `"캐시 워밍 후 3회 평균"`.
나머지 14건은 method 가 전부 비었다. 라운드 2 재채점 결과가 실제 데이터에서도 유지됐다.

## 못 잰 것

| | |
|---|---|
| ⬜ 에디터로 **직접 쓴** 글에 대한 파이프라인 실행 | 심은 글은 전부 API 로 넣어 `htmlContent` 가 비어 있다. 블록 융합 계측만 에디터 글로 했다 |
| ⬜ 굵게·표가 **값을 감싼** 문서의 재현율 | 게이트가 깨지는 조건은 알아냈지만(비공백 문자), 실제 문서에서 얼마나 깎이는지는 안 쟀다 |
| ⬜ 배치 크기 기준 | 12문서에서 안 났다고 100문서에서 안 난다는 근거가 없다 |
| ❌ 「노이즈가 추출을 N% 깎는다」 | 실행 1회씩이다. 방향만 말한다 |

## 오늘 한도

`gemini-3.6-flash` · `gemini-3.5-flash` 둘 다 `RESOURCE_EXHAUSTED` 로 소진돼 `gemini-3.1-flash-lite` 로 폴백됐다.
재시도 10회를 태우고 나서다. **폴백이 조용히 돌면 두 실행의 모델이 달라진다** — `usage.byModel` 을 결과 JSON 에 항상 남긴다.
