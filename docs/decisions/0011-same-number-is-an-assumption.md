# 0011 · 「같은 숫자면 같은 측정」은 가정이다 — 그 판단도 모델에게 넘긴다

- 날짜: 2026-09-11
- 상태: 채택 · **구현 대기**(상위 모델 하루 한도 복구 후)

## 맥락

「근거 없음」 판정에는 면제가 하나 붙어 있다.

```js
const grounded = new Set(groupClaims.filter(hasMethod).map(valueOf))
return groupClaims.filter((c) => !c.isTarget && !hasMethod(c) && !grounded.has(valueOf(c)))
//                                                               ↑ 같은 값이 어딘가 방법과 함께 있으면 면제
```

킥오프 글의 `820ms` 에는 방법이 없다. 그런데 쿼리 프로파일링 글에 같은 `820ms` 가
`스테이징 · 동시 10 · 캐시 미적용` 과 함께 있어서 **안 걸린다.**

**값만 보고 면제한다. 방법 내용은 안 본다.**

## 왜 문제인가

[0004](0004-context-sameness-goes-to-the-model.md) 로 정반대 규칙을 넣었다.
`320ms(캐시 미적용)` 와 `280ms(캐시 워밍 후 3회 평균)` 는 **잰 방법이 다르니 견주지 않는다.**

**비교할 때는 방법을 따지는데, 면제할 때는 안 따진다.** 같은 파일 안에서 두 규칙이 다른 말을 한다.

그리고 킥오프의 `820ms` 가 프로파일링과 같은 조건에서 잰 것인지는 **아무도 모른다.**
킥오프 글에 조건이 아예 없기 때문이다. **「모른다」를 「같다」로 치고 있다.**

## 결정

면제 기준을 **값**에서 **조건 묶음**으로 옮긴다.

```
지금    면제 = 「같은 값이 방법과 함께 어딘가 있다」
바꾼 뒤  면제 = 「같은 조건 묶음 안에 방법 적힌 값이 있다」
```

묶기 모델이 이미 그룹을 조건별로 가른다. 지금은 방법이 안 적힌 값을 **무조건 「조건 미기재」로 몬다.**
그 제약을 푼다 — 모델이 킥오프의 `820ms` 를 「스테이징 · 동시 10 · 캐시 미적용」 묶음에 넣을 수 있게 한다.

넣으면 면제, 안 넣으면 「근거 없음」으로 걸린다.

## 지어내기와 어떻게 다른가

**모델이 `method` 문자열을 만들어 붙이는 게 아니다.** 그건 지금도 금지고 계속 금지다.

모델이 하는 건 「이 두 주장이 같은 측정을 가리키나」라는 같다/다르다 판단이고,
내놓는 것은 **`claimId` 묶음**이다. 지표 묶기 · 조건 묶기와 같은 종류라 **참조 게이트가 그대로 걸린다.**

## 위험과 완화

모델이 아무거나 같은 묶음에 넣으면 **미탐이 는다.**
그래서 [0006](0006-do-not-delete-what-the-model-split.md) 그대로 간다 — 면제된 값에 **왜 면제됐는지를 화면에 적는다.**

> `820ms` — 같은 값이 「쿼리 프로파일링」에 방법과 함께 있고, 같은 측정으로 봤습니다.

사람이 보고 「아니다」 할 수 있어야 한다.
