# 0012 · 자동 실행은 웹훅이 아니라 폴링이다 — 지문 비교부터 넣었다

- 날짜: 2026-09-11
- 상태: 부분 채택 (지문 비교는 구현, 크론은 안 함)

## 맥락

「플로우에서 업무 글을 쓰면 자동으로 감사가 돌게 할 수 있나」를 확인했다.

## 웹훅은 방향이 반대다

플로우에 웹훅이 있다(`api.flow.team/docs/webhook`). 그런데 **들어오는 쪽**이다.

```
GitHub push · GitLab merge_request · Jenkins 빌드 완료  →  플로우 게시글/채팅
```

`x-flow-webhook-token` 으로 인증하고 요청 본문의 `text` 필드를 글 본문에 찍는다.
**외부 이벤트를 플로우로 받는 통로**지, 플로우에서 글이 작성됐을 때 외부 서버를 부르는 기능이 아니다.
User API 목록에도 이벤트 구독이 없다 — 전부 조회/생성 REST 다.

## 그래서 폴링이다

```
크론 → GET /user/posts/projects/{id}   (플로우만, Gemini 예산과 무관)
     → 마지막으로 본 지문과 다른가?
     → 다르면 감사 1회 (Gemini 2회)
```

**감지는 공짜고 감사만 예산을 쓴다.** 새 글이 없으면 모델을 안 부른다.
하루 20회 한도에서 **최대 10번**까지 감사할 수 있다(추출 1 + 묶기 1).

## 자동 등록은 안 한다

**플로우에 삭제 API 가 없다.** 지금도 그래서 미리보기가 기본값이고 사람이 눌러야 쓴다.
자동 등록을 붙이면 프로젝트가 도구 출력으로 덮이고 되돌릴 방법이 없다.

자동 실행의 가치는 정확히 이것까지다 — **사람이 열어 보기 전에 이미 감사가 끝나 있다. 등록은 여전히 사람이 누른다.**

## 지문 비교는 먼저 넣었다

크론은 배포된 환경에서만 검증되므로 안 만들었다. 그런데 **부품 하나는 지금 필요했다.**

라이브 감사가 새로고침마다 모델 2회를 태우고 있었다. 10분 TTL 은 인스턴스 메모리라
서버리스에서는 콜드스타트마다 비고, **하루 10번이면 한도가 마른다.**

그래서 `api/audit.js` 가 모델을 부르기 전에 **글 목록 지문**(`postId:수정시각:댓글수`)을 먼저 본다.
같으면 모델을 한 번도 안 부르고 캐시를 돌려준다. 배지가 그렇게 적는다.

> 방금 플로우를 읽었습니다 · 글이 그대로라 앞서 돌린 결과입니다

**실측**: 콜드 12.9초(모델 2회) → 두 번째 요청 **0.1초(모델 0회)**.
플로우 조회가 실패하면 TTL 판정만 믿고 캐시를 쓴다 — 여기서 터져 라이브 경로 전체가 죽는 것보다 낫다.

크론을 얹을 때 필요한 지문 비교가 이미 여기 있다.
