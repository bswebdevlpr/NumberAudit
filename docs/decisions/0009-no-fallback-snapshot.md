# 0009 · 모델 폴백으로 만든 스냅샷은 기준본으로 쓰지 않는다

- 날짜: 2026-09-11
- 상태: 채택

## 맥락

[0008](0008-tables-become-rows.md) 을 검증하려고 감사를 다시 돌렸는데, 상위 모델 하루 한도가 차 있었다.

```
429 RESOURCE_EXHAUSTED
quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier
model: gemini-3.6-flash · quotaValue: 20
```

폴백이 돌아 `gemini-3.5-flash` 로 전부 처리됐고, 표 값은 살아났는데 **다른 곳에서 4건이 죽었다.**

```
✗ 250ms  인용 "250ms"   ← 원문: 「검색 응답 250ms로 개선」
✗ 47회   인용 "47회"    ← 원문: 「요청당 쿼리가 47회 나갑니다」
✗ 3회 · 2배
```

## 관측

**모델을 내리면 인용이 짧아진다.** 상위 모델은 문장째 인용했고, 아래 모델은 값만 냈다.
게이트 조건 ③(값 외 문맥 3자)이 그걸 버렸다.

게이트는 제 일을 했고 손해는 모델 쪽에서 났다. **참인 주장 4건이 폐기됐다.**

## 결정

그 실행본은 저장본으로 쓰지 않는다. 한도가 복구되면 상위 모델로 다시 뽑는다.
다만 **버리지 않고 기록한다** — 근거 파일은 세션 작업 폴더에 남겼고, 관측은 README 에 적었다.

## 왜 이 관측이 중요한가

라이브 감사는 함수 상한(60초) 때문에 **빠른 모델로 돈다.**
지금까지 README 는 「라이브가 저장본보다 덜 뽑히는 경우가 있다」고만 적었는데,
**왜 덜 뽑히는지**가 이걸로 설명된다 — 모델이 덜 찾는 게 아니라 **인용이 짧아져 게이트에 걸린다.**

표본은 실행 한 번이다.
