# 0004 · 측정 조건이 같은지는 모델이 정하고, 값이 갈렸는지는 코드가 본다

- 날짜: 2026-09-11
- 상태: 채택

## 맥락

판정이 `320ms(스테이징 · 동시 10 · 캐시 미적용)` 와 `280ms(캐시 워밍 후 3회 평균)` 를
한 줄에 놓고 「값이 갈림」이라고 말하고 있었다. 잰 방식이 다른 두 숫자는 **애초에 견줄 수 없다.**

원인은 `method` 를 **있냐 없냐로만** 쓰고 있었다는 것이다. 내용은 한 번도 읽지 않았다.

```js
const hasMethod = (c) => Boolean(String(c.method ?? '').trim())
```

작은 문제가 아니었다. 생성되는 업무 6건 중 5건이 「값이 갈림」이다.

## 결정

**조건 동일성 판단을 모델에게 넘긴다.** 코드는 갈렸는지 여부만 본다.

묶기 호출이 그룹을 내면서 그 안의 조건 묶음까지 같이 낸다 — **호출은 2회 그대로다.**

```json
{ "metric": "p95 응답시간", "claimIds": [...],
  "contexts": [
    { "condition": "스테이징 · 동시 10 · 캐시 미적용", "claimIds": ["C007","C019"] },
    { "condition": "캐시 워밍 후 3회 평균",            "claimIds": ["C012"] },
    { "condition": "조건 미기재",                     "claimIds": ["C002","C005"] } ] }
```

## 왜 코드로 안 하나

문자열 완전 일치는 놓친다.

```
스테이징 · 동시 10 · 캐시 미적용
스테이징에서 동시 10 으로, 캐시 없이     ← 같은 조건, 다른 글자
```

유사도로 가면 임계값을 손으로 정해야 한다. 이 저장소는 감으로 정한 임계값에 한 번 데였다
(인용 길이 하한 `6자` 가 `"참석 5명."` 을 잘랐다 — [`docs/measurement.md`](../measurement.md)).
조건 유사도에는 그 실측이 없다. 감으로 0.8 을 적으면 같은 실수를 반복한다.

## 경계가 깨지는가

안 깨진다. **「판정은 코드가 한다」를 너무 넓게 말했던 것**이고, 실제 선은 이렇다.

> 견줄 대상을 고르는 건 모델이 한다. 견준 결과를 「같다/다르다」로 떨어뜨리는 자리에 코드가 선다.

지표 묶기가 이미 그렇다. 조건 묶기는 **같은 자리에 한 종류를 더 얹는 것**이다.

그리고 모델이 내는 건 조건 설명문이 아니라 **claimId 묶음**이라,
참조 게이트를 세 번째로 그대로 건다 — 없는 ID · 그룹 밖 ID · 한 그룹 안 중복 배정 · 누락.

## 결과

`contexts` 가 비면 조건 축을 안 쓴 것과 같아진다. 판정이 예전 동작으로 떨어지고 화면은 그대로 산다.

화면과 업무 본문이 이렇게 바뀌었다.

```
같은 조건끼리 견줬을 때 320ms · 820ms 가 함께 적혀 있습니다.
280ms 는 잰 조건이 달라 견주지 않았습니다.
```

조건이 전부 「미기재」인 그룹에서는 예전 문구(「같은 지표에」)를 쓴다 — 조건 축이 실제로 일한 경우에만 「조건」이라고 부른다.
