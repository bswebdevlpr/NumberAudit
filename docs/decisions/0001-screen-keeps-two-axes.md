# 0001 · 배포 화면에는 목적을 두 줄만 남긴다

- 날짜: 2026-09-10
- 상태: 채택

## 맥락

화면에서 설명을 전부 걷어내고 목적만 제목처럼 남기기로 했다. 설명은 [README](../../README.md) 가 맡는다.

그런데 그러고 나니 **화면만 열어 본 사람에게는 이 도구가 무엇을 하는지가 0줄**이 됐다.
링크를 하나만 여는 사람은 저장소가 아니라 화면을 연다. 화면이 자기 목적을 한 번은 말해야 한다.

## 결정

화면에 **두 줄만** 넣는다. 설명이 아니라 두 줄이다.

| 라벨 | 내용 |
|---|---|
| 푸는 문제 | 같은 숫자가 글마다 다르게 적히고, 그 숫자를 어떻게 쟀는지는 어디에도 남지 않습니다. |
| 쓰는 방법 | 플로우 API 로 글과 댓글을 읽고, Gemini 가 수치를 뽑고, 인용이 원문에 실재하는지는 코드가 확인합니다. |

자리는 첫 화면의 「예시 불러오기」 바로 위. 워크플로가 시작되기 직전이다.

「쓰는 방법」 한 줄이 **플로우 · 모델 · 코드의 역할 분담까지 같이 말한다** — 이 도구의 경계 주장이 화면에서도 한 번은 나온다.

## 대안과 버린 이유

- **아무것도 안 넣는다** — 화면만 본 사람에게 목적이 안 남는다.
- **설명 절을 되살린다** — 걷어낸 것을 되돌리는 것이고, 화면이 다시 길어진다.
- **푸터에 넣는다** — 읽히지 않는다.

## 결과

「푸는 문제」 첫 판은 출처 이야기만 적어 목적의 절반을 빠뜨렸다.
판정이 실제로 내놓는 결과가 `어떻게 쟀는지 없음` · `값이 갈림` 둘인데 한쪽만 말한 것이다.
두 갈래를 다 담도록 고쳤다. **화면 문장과 판정 출력이 같은 것을 말한다.**

부수 효과로 데스크톱 첫 화면의 빈 여백이 채워졌다.
