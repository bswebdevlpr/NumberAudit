# 0013 · 남의 API 키를 받지 않는다

- 날짜: 2026-09-11
- 상태: 채택

## 맥락

「API 키를 입력받아 그 사람의 플로우 프로젝트를 감사해 주면 어떤가」를 검토했다.
기술적으로는 쉽다 — 키와 `projectId` 를 받아 같은 파이프라인을 돌리면 된다.

## 결정

**받지 않는다.**

## 이유

**플로우 API 키는 읽기 전용이 아니다.** 그 키 하나로 그 사람의 모든 프로젝트를 읽고, 글을 쓰고,
업무 상태를 바꿀 수 있다. 서버가 그걸 잠깐이라도 들고 있으면 **그 순간부터 내 책임**이다 —
전송 · 로그 · 메모리 · 에러 스택 어디로도 새면 안 된다.

**키는 화면에 나타나면 안 되는 것이다.** 이 저장소는 키가 로그·리포트·에러 메시지 어디에도 안 찍히게
`redact()` 까지 두고 있다. 그런데 **남의 키를 입력받는 화면**은 그 방향의 정반대다 —
키를 안 보이게 하려고 애쓰면서 키를 달라고 하는 셈이다.

**Gemini 쪽이 안 풀린다.** 남의 프로젝트를 감사해도 모델은 **내 키로 돈다.** 하루 20회라 몇 명이면 마른다.
그럼 Gemini 키도 받아야 하고, **받는 키가 둘**이 된다.

## 대신 이미 있는 두 경로

**「내 글로 해보기」** — 키 없이 자기 글을 붙여넣어 추출 · 게이트 · 판정을 그대로 돌린다.
「내 데이터로 해보고 싶다」의 대부분을 안전하게 준다. 호출 1회고 상위 모델로 돈다.

**로컬 CLI** — `npm run audit -- <projectId>`. 자기 키를 `.env` 에 넣고 자기 컴퓨터에서 돌린다.
**키가 밖으로 나가지 않는다.** README 「직접 돌려 보려면」에 있다.

## 남기는 이유

「할 수 있는데 안 했다」는 결정은 코드에 흔적이 안 남는다. 그래서 여기 적는다.
이 저장소가 계속 해 온 일이 그거다 — **할 수 있는 것과 하면 안 되는 것의 선을 긋고 그 자리를 문서에 남기는 것.**
