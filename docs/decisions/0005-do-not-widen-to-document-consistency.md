# 0005 · 문서 정합성으로 넓히지 않는다 — 넓히는 기준만 정확히 한다

- 날짜: 2026-09-11
- 상태: 채택

## 맥락

이 도구의 출발은 수치가 아니라 **연관 문서가 서로 어긋난 채 굳는 것**이었다 —
ADR 과 그 뒤에 바뀐 설계, 같은 문서의 여러 판, ERD 와 인터페이스 명세.

조건 동일성 판단을 모델에게 넘기기로 하면서([0004](0004-context-sameness-goes-to-the-model.md)),
「수치에서 멈춘 이유」로 들었던 근거가 흔들렸다.
그때 적은 근거는 「수치가 코드로 검산할 수 있는 거의 유일한 주장 종류라서」였는데,
묶는 일은 이미 모델이 하고 있었으니 그 문장이 뭉툭했던 것이다.

## 결정

넓히지 않는다. 대신 **기준을 실제로 그을 수 있는 문장으로 바꾼다.**

> 견줄 대상을 고르는 건 모델에게 넘긴다.
> 견준 결과를 「같다/다르다」로 떨어뜨리는 자리에는 **코드가 설 수 있어야 한다.**

이 자로 재면 갈린다.

| | 견줄 대상 고르기 | 마지막 한 걸음 |
|---|---|---|
| 지표 묶기 · 조건 묶기 | 모델 | — (고르기가 전부) |
| 수치 대조 | 모델이 고른 것 안에서 | **코드** — `320 ≠ 280` |
| ADR ↔ ERD 모순 | 모델 | **모델** ← 여기서 게이트가 지킬 것이 없어진다 |

## 넓어지는 부분은 있다

문서 정합성 전부가 의미 판단은 아니다. **식별자형 주장**은 수치와 성질이 같다.

```
필드 이름   user_id  vs  userId
타입        BIGINT   vs  UUID
엔드포인트   /api/v1/users  vs  /api/users
```

값이 자유 텍스트가 아니라 식별자라 마지막 한 걸음이 코드로 떨어진다.

## 왜 지금 안 하나

비용이 판정 로직이 아니라 **그 앞 전부**에 있다.

```
지금    { metric, valueText, unit, scope, method, isTarget, quote }
식별자  { name, kind(필드/타입/경로), declaredIn, quote }
```

축이 다르면 추출 스키마 · 프롬프트 · 묶기 · 판정 · 업무 문안을 한 벌 더 만들어야 한다.
재사용되는 건 게이트와 수집 · 정제뿐이다. 반쯤 만들면 「아직 못 잰 것」만 길어진다.
